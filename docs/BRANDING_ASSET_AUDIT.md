# Branding asset audit

## Conclusion

The app now has one production branding source and one Expo-controlled Android
pipeline. QA and production share the same launcher, splash, monochrome, and
notification artwork. QA differs only by the intentional `.qa` application ID
suffix and `3azza QA` display name.

The canonical source is `assets/branding/brand-master.png`: the 1254x1254
transparent blue front-view scooter with the `3azza` plate. All runtime
derivatives are generated by `scripts/generate-branding-assets.py`.

## Root cause and evidence

There was no build-profile-specific Expo icon configuration. The only EAS
profile difference is output type: `preview` builds an APK and `production`
builds an AAB. There is no `app.config.js`, `app.config.ts`, or icon-related
environment override.

The apparent QA/release mismatch came from three separate issues:

1. The previous adaptive configuration put an already composed, padded icon in
   `backgroundImage` and supplied a completely transparent foreground. This is
   legal but non-standard. The fallback legacy icon was generated from the same
   padded composition, making the scooter extremely small, while adaptive
   launchers treated the full composition as a background layer.
2. The Google Play listing icon was still `store-assets/play-icon-512.png`, the
   obsolete blue chevron mark. A listing icon is independent of the launcher
   icon packaged in an AAB.
3. The ignored generated `android/` tree contained unused launcher resources
   from older production and QA experiments. The QA manifest did not reference
   those files, but their presence made the pipeline ambiguous. A clean
   prebuild removed them.

The existing production artifact
`artifacts/3azza-2.3.4-15.aab` (SHA-256
`0192DF63D8ED60DE97BE7E32EA0C0D7BF35371C413EF3D39065C92BEA0648162`)
was inspected directly. It already contains the current scooter in its launcher
background and splash; it does not contain the old chevron or a default Expo
icon. Its adaptive foreground is blank and its legacy launcher rendition is
undersized. Therefore an old icon observed on an installed release is not
evidence of an EAS QA/production config split; it is more likely an older
installed build or launcher cache. The stable `MainActivityLauncher` alias is
retained to give vendor launchers a fresh component identity.

## Configuration authority

`app.json` is the source of truth for Expo and clean EAS builds. It points only
to stable production filenames under `assets/branding/` and configures:

- a standard full-square launcher icon;
- a transparent adaptive foreground over solid navy;
- a true monochrome adaptive layer;
- the plugin-based Expo splash screen;
- the web favicon; and
- the Android notification small icon and tint.

The native `android/` directory is ignored by Git and excluded by `.easignore`.
It is generated, not authoritative. `expo prebuild` clears it in this checkout,
so the existing side-by-side QA build type is now reproduced by
`plugins/with-android-qa-build-type.js`. No QA icon override is generated.

## Google Play asset status

Current Google Play requirements checked for this audit:

- App icon: 512x512, 32-bit PNG, at most 1024 KB, full square with no manually
  rounded corners or outer drop shadow.
- Feature graphic: 1024x500, JPEG or 24-bit PNG without alpha.
- Screenshots: at least two are required; four 1080px-or-larger 9:16 phone
  screenshots are recommended for app promotion surfaces.

`store-assets/play-icon.png` and `store-assets/feature-graphic.png` meet those
file requirements. The four existing 1200x2280 phone screenshots remain real
product captures and do not display the obsolete chevron logo. Tablet
screenshots are not currently present; they are optional listing work unless
the Play Console/device targeting for this release specifically requires a
large-screen set.

Official references:

- https://support.google.com/googleplay/android-developer/answer/9866151
- https://developer.android.com/distribute/google-play/resources/icon-design-specifications

## Regeneration and release

Regenerate deterministic derivatives:

```powershell
python scripts/generate-branding-assets.py
npx expo prebuild --platform android --no-install
```

Production EAS build:

```powershell
npx --yes eas-cli@21.8.0 build --platform android --profile production
```

This branding release advances `expo.android.versionCode` to 16. Launcher caches
can survive an upgrade; when visually verifying an icon change, first remove and
re-add the launcher shortcut, restart the launcher/device, or uninstall the old
app only if preserving its local data is not required.
